# Semweft 路线图、风险与决策

> 本文：版本规划、成功指标、风险与待决策事项。 [返回文档索引](../semweft.md)

## 1. 版本规划

当前按用户确认的 [20 项产品功能清单](product-next.md)顺序开发，逐项记录已完成范围和待补齐部分。

|版本|范围|验收标准|
|---|---|---|
|v0.1|Rust 主语言；Go 实验性；初始化与信任、配置、共享 daemon、索引与健康报告、能力与状态查询、位置/符号导航、受限调用图、符号/diff 候选影响、Cargo 目标与结构地图、预算上下文、MCP stdio 和 CLI；人工可读输出（text/Markdown、依赖图 Mermaid/DOT 导出、impact Markdown 报告）|Rust 至少 3 个真实仓库，20 个标注改动任务做初始闭环验证，满足正式语言支持标准；不接入任何 Agent，在其中至少 2 个仓库上仅用 CLI 完成陌生仓库上手与改动复核各一次，结论可回到源码，缺口与截断显式披露；验证多客户端同索引与单写入锁、断连和 daemon 恢复、配置与范围变更、CLI 重建和退出码、历史引用显式请求、跨文件失效与固定视图、位置解析、diff 两侧、等待总预算、信任降级和分页/预算截断|
|v0.2|Go 正式支持；限定签名与依赖规则、find_paths、测试候选建议、CI JSON/Markdown/SARIF 报告；trait 实现列表、公开 API 清单与循环依赖检测；风险评分实验性|Go 达到同样语言门槛；规则有独立正反例与证据不足案例；相同 Agent 条件下任务成功率不下降，漏改、候选阅读成本与 Token 消耗分别报告；无 Agent 人工任务对照 IDE 加 rg 基线，分别报告上手与复核的正确率和耗时|
|v0.3|TypeScript / JavaScript；架构规则；自包含静态 HTML 报告（依赖图、影响报告、缺口汇总），先于桌面端交付；桌面审查台首版，仅影响列表、规则结果、代码与诊断侧栏及人工回传|语言支持分项验收；20 个标注改动做初始人工对照实验并规划扩大样本，审查正确性不下降；代码变化后旧批准失效，通知与拉取按客户端实测|
|v0.4|Python；Thrift / Protobuf 解析、限定生成器映射、契约兼容规则与影响视图|在有独立字段真值的多服务仓库验证直接访问、accessor、透传与映射失败；分别报告契约/类型/字段召回和错误率，不宣称发现所有外部消费者；发布编排顺延|
|v1.0|按外部团队验证结果选择运行时融合、IDE、团队服务和条件发布建议；Java / Kotlin 分项适配|至少 3 个外部团队持续使用；满足权限与审计要求，新增能力各自有独立基准和明确边界|

**排期方式**：先完成查询闭环，再按语言和模块逐项验收；面向人的输出随各版本的事实能力同步交付，不单独成线；原型与真实仓库测量完成后，依据人员和工作量确定日期。达不到门槛的能力保持实验性或顺延，桌面、向量检索和查询语言在对应版本立项。

**当前进展**：v0.2 的 20 项产品功能（修改核验、调用路径、测试候选、CI 报告、风险评分、公开 API、循环检测、架构规则与基线、Agent 护栏、保护区域、Hooks、审查归档、静态 HTML、Go/TS/JS 语言入口、Protobuf 契约）均已有首版入口，各项已完成范围与未覆盖部分逐项记录于 [20 项清单](product-next.md)。Go/TS/JS 保持 experimental，仍缺独立复核、更广的构建验收和远程生产器 CI，不能用小样本或 fixture 通过替代正式验收；风险评分只用于审查优先级排序，非概率、未经真实任务校准。

**前置原型门槛**：v0.1 正式实现前，先完成编辑期语义刷新原型，通过[语言与 IDL 支持](language-support.md)第 5.4 节的一致性验证；原型同时确定 Rust 语义接入方式，并为图存储方案提供写入与查询负载。未通过时不定稿存储与调度方案。

v0.1 不交付 verify、框架入口、GUI、IDL、本地 HTTP MCP 或团队远程 API。进程与配置基线见[架构设计](architecture.md)第 1 节；LSP 与内嵌后端的选择及故障边界仍由前置原型确定。

## 2. 成功指标

首版的 20 个任务用于验证工作流与故障模式；正式效果评估另行登记样本量、重复次数和检验方案，并报告置信区间。下表长期目标用于研究方向，验收与继续投入采用预先登记的门槛；通用承诺边界见[证据模型](evidence-model.md)第 2.3 节。

|维度|指标|目标|
|---|---|---|
|Agent 效果（主指标）|内部跨文件改动任务集的成功率与漏改率，相同 Agent 条件对照|成功率不下降；漏改率的最小改善幅度与统计检验方案在独立基线建立后、正式评估前登记|
|Agent 效果（参考）|SWE-bench Multilingual、Multi-SWE-bench 的对应语言子集成功率|不下降；这类任务以单仓库局部修复为主，只作外部可比参考|
|Agent 成本|完成同类任务的 Token 消耗，计入工具 schema、结果与重试|成功率不下降时降低；最小改善幅度在独立基线建立后、正式评估前登记|
|正确性|漏改点数 ÷ 独立标注的应改点数，同时报告误改、候选错误率和未解析率|长期目标 ≤2%；已知缺口披露与真实遗漏分别统计|
|审查效率|v0.3 审查台发布前以相同任务和正确性条件建立对照；初始 20 个标注改动仅验证流程|长期目标缩短 50%；扩大样本后报告置信区间|
|审查判断|评审者能否正确区分已检查、待确认和未知范围；统计错误批准与错误驳回|准确判断目标 ≥80%；问卷信心单独作为补充指标|
|无 Agent 使用|不接入 Agent 时，陌生仓库上手与改动复核任务的正确率和耗时，对照 IDE 加 rg 基线；Token 成本为零，不作为收益计入|正确率不低于基线；耗时的最小改善幅度在独立基线建立后、正式评估前登记|
|性能|百万行仓库索引和查询延迟|达到[质量目标与评测](quality.md)第 1 节目标|
|生态采用|持续使用的外部团队数，以及被主流 Agent 框架或 IDE 集成的数量；下载量、star 只作传播数据|v1.0 至少 3 个外部团队、3 个集成|

**继续投入门槛**：v0.1 完成后、扩展 Go 与规则核验之前，在预先登记的内部任务集上做对照。样本量、重复次数和最小改善幅度在实验前确定，主基线为 Agent 内置的 LSP 与代码索引（见[产品需求](product.md)竞品比较）。同时满足以下条件才继续按路线投入：

- 任务成功率不低于基线

- 漏改率或 Token 消耗至少一项达到预先登记的最小改善幅度，并报告置信区间

- 计入首次安装、全量索引耗时、常驻进程资源和版本维护后，每个成功任务的总耗时与成本仍不高于基线

无 Agent 路径与 Agent 路径分别登记门槛并在同一轮评估：人工任务正确率不低于 IDE 加 rg 基线，且耗时达到预先登记的最小改善幅度。两条门槛在实验前同时登记，结果分别报告，不在评估后用一侧替代另一侧。Agent 门槛未达而无 Agent 门槛达到时，可按 CLI、CI 与 HTML 报告为主的范围继续投入，但不扩展语言；两侧都未达到时按下文处理。

未达到时不扩展语言范围，先分析失败样本：收益集中在跨服务场景时，按第 4 节评估提前 Go + Thrift 契约映射；没有可测收益时收缩范围或停止投入。

## 3. 风险与应对

|风险|应对与验收证据|
|---|---|
|来源等级被误认为正确率或完整性|接口与视图采用证据模型第 2 节的维度与状态，评测验证用户是否正确理解|
|动态机制、外部消费者和缺失构建输入造成未知遗漏|显示未解析点、配置与仓库边界，独立标注测量真实遗漏|
|跨文件或构建变更导致过期语义关系|反向依赖失效、配置级失效与查询版本固定；无法准确确定影响时扩大 pending 范围|
|SCIP/工具链版本、错误与生成物映射影响 L3|锁定版本、独立进程、取消与回归；失败保留当前语法事实并披露语义缺口，不静默复用旧证据|
|批量 SCIP 缺少编辑期细粒度增量，语义证据长期 pending|Rust 常驻语义服务按需刷新；Go v0.1 实验路径按项目重建，成功后发布新语义视图；失败与工具阻断分别披露，报告 pending 持续时间分布|
|首版范围过大|Rust 查询闭环先行；Go 实验性；桌面、向量、GQL 和 IDL 按门槛后置|
|面向人的输出扩大首版范围|只增加同一响应的渲染层与导出格式，不新增事实类型或第二套 schema；HTML 报告排在 v0.3，TUI、度量、热点与历史按原计划后置|
|无 Agent 场景的成熟对手更多（IDE、Understand、Sourcegraph、cargo-modules）|不以结构浏览为卖点；人工任务对照 IDE 加 rg 基线，证明证据标注、缺口汇总和可复现报告的增量价值|
|基准只对齐自身索引或依赖弱对手|独立真值、成熟符号基线、失败样本纳入；报告质量、成本和置信区间|
|图候选和路径爆炸|限制查询预算，验证稳定截断、分页续查与候选集合大小|
|契约依赖误当实际服务依赖，发布排序前提缺失|生成器映射、部署映射分开；兼容规则先行，阶段约束与缺失条件显式报告|
|Agent 厂商已有或自建类似能力|通过开放接口与真实对照实验验证价值，不把协议或 GUI 当作排他壁垒|
|GUI 平台、API 和性能不确定|选定版本后验证输入、列表与代码视图；桌面进程与共享服务隔离，图布局后续测量|
|外部索引器、原生库与模型使安装复杂|区分核心二进制与 L3/模型资源，先验证最小安装；不预设单二进制包含所有语义能力|
|图存储的快照与增量写入成本不确定|基于语义刷新原型的真实负载比较邻接表、redb 等方案，测量视图保留、写入、查询、磁盘与内存成本；原生依赖的分发成本一并记录|
|索引执行不受信任仓库的构建脚本和过程宏|用户通过 init 或 trust 预先确认；MCP 不交互授权，未确认只提供已实现的 L1/L2；可选沙箱运行外部索引器|
|代码索引与外部工具存在权限边界|只读 API、显式工具运行配置；团队版按仓库鉴权与审计，共享索引继承源码访问约束|
|依赖或模型许可证影响分发|按锁定版本检查依赖、语法和权重；cargo-deny 辅助检查，模型与非 Cargo 资源另行记录|

## 4. 待决策事项

本节 [x] 表示已确定的设计约定，[ ] 表示待决策或验证；实现交付状态仍以各版本验收为准。

- [x] 关系证据的四个维度、冲突与统计口径，以及范围与核验状态，统一采用[证据模型](evidence-model.md)第 2 节

- [x] 输入快照与语义进度分离，查询与游标固定不可变分析视图；等待共享请求总预算，diff 显式选择两侧，上下文按 tokenizer 计量，见证据模型第 3 节与接口规格第 1 节

- [ ] 原型测量后锁定工具默认预算、视图回收阈值及性能/质量门槛，并回填能力清单与配置默认值

- [x] 不使用 AI 的开发者与评审者是正式目标用户：核心事实与报告不依赖模型；人工格式是同一响应的渲染层，共用 schema_version；v0.1 起提供 text/Markdown 与依赖图导出，v0.3 先交付静态 HTML 报告，见[接口规格](interfaces.md)第 2.2 节

- [ ] 偶尔使用的人工场景是否需要不常驻 daemon 的一次性 batch 模式；需先测量首次索引与 daemon 拉起各自的成本

- [x] 产品名采用 Semweft，命令、crate、包和配置统一使用 semweft（公开命名核查见[命名与公开核查](product.md#5-产品命名与公开核查)）

- [ ] 实际发布前完成目标地区商标核查，以及包名、账号和域名注册

- [ ] 图存储方案：自研邻接表还是基于现有嵌入式数据库；在编辑期语义原型确定增量写入与查询负载后决定

- [ ] GQL 语法：兼容 Cypher 或 ISO GQL 子集，还是设计更简单的专用语法；同时确定正式名称，避免与 ISO GQL 重名

- [ ] 每个语言与生成器适配器的能力清单、正式支持门槛和维护版本；Java/Kotlin 不提前扩充首版

- [ ] 团队版的商业化边界：哪些能力开源、哪些属于企业版

- [ ] 建立内部跨文件改动任务集与基准仓库（主指标），固定外部参考基准的 revision 与子集（见[质量目标与评测](quality.md)第 2 节），建立漏改率、Token 消耗和审查耗时的基线

- [ ] 桌面审查台和 IDE 插件的分工：哪些视图放桌面端，哪些放进 IDE

- [x] 人工审查通过 CLI 到本地 daemon 提交，固定两侧快照、版本对与报告哈希；以 get_review_result 拉取，输入变化或采用新证据时重新审查，见[接口规格](interfaces.md)第 1.6 节

- [ ] 验证审查记录状态与失效协议的实现，以及资源更新通知能否被目标客户端消费

- [ ] 是否在 v0.3 静态 HTML 报告之上提供可交互的 Web 版审查视图（例如从 PR 链接直接打开），与桌面端共享布局算法

- [ ] 外部 SCIP 索引器的分发方式：随 Semweft 打包、按需下载，还是要求用户自行安装；以及版本锁定策略

- [ ] 桌面审查台的 Windows 交付时间点与架构矩阵：上游已支持 Windows，按选定 gpui-kit 版本验证本项目的构建、输入与发布，依据见[质量目标与评测](quality.md)第 1 节

- [ ] 语言与 IDL 顺序：若首批用户以 Go + Thrift（Kitex）服务为主，评估将 Go 正式支持与 Thrift 契约映射提前，以尽早验证跨服务这一差异化方向；当前路线仍为 Rust 先行

- [ ] Rust 编辑期语义的接入方式与进程边界：LSP 或内嵌 ra_ap_*，内嵌于 daemon 或独立 worker；比较覆盖、版本维护、合计内存和故障恢复，由前置原型决定

- [x] v0.1 每个 Cargo 工作区一个共享 daemon，stdio MCP 桥接；配置、自动拉起与退出、存储和 IPC 路径见架构第 1 节。本地 HTTP MCP 后置，与团队远程 API 分别排期

- [x] 历史证据通过 find_references 显式请求并与主视图分开；重新索引走 CLI 控制通道；diff CLI 语法与退出码见接口规格
