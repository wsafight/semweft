# Semweft 质量目标与评测

> 本文：非功能需求、基准口径与实验设计。 [返回文档索引](../semweft.md)

## 1. 非功能需求

以下为待验证目标，不是已测结果。基准固定 CPU、内存、SSD、OS、编译配置、仓库 revision、文件与关系数量，并分别报告冷启动、热缓存、语法与语义阶段。初始参考为 8 核、16GB 内存与本地 SSD；选择具体机器后锁定型号，不能只按代码行数比较不同语言。

|类别|目标|衡量方式|
|---|---|---|
|全量索引速度|100 万行代码，语法层索引在 60 秒内完成（8 核机器）；语义层（SCIP）索引耗时取决于外部索引器，单独统计，目标不超过该仓库一次全量编译耗时的 1.5 倍，期间先用语法层结果提供服务|基准仓库测试|
|语法增量延迟|不超过 5,000 行文件的普通编辑，新的语法事实 P95 500ms 内可查；大型文件与配置变更单独报告|文件事件到新语法版本可查询，含 debounce、解析、存储与发布|
|语义刷新|分别测量常驻语义后端按需刷新与 SCIP 项目重建；目标是在 Agent 一次编辑-编译循环内让受影响证据回到 current，阈值由原型测量确定；报告排队、计算与 pending 持续时间的 P50/P95/P99|固定编辑集与后端版本，验证跨文件失效；与语法延迟分开验收|
|查询延迟|固定快照下符号与首屏引用查询 P95 50ms，3 层调用图 P95 200ms；图查询默认至多 1,000 个节点，超限显式截断|固定返回规模；分开报告缓存、分页与超时|
|内存占用|100 万行代码时引擎常驻内存初始参考目标 1.5GB，支持按需加载；外部语义服务与独立 worker 分别测量并给出合计，同进程内嵌按整体 RSS 测量；最终资源上限由接入原型确定|分进程 RSS 与所有 Semweft/语义进程合计，注明后端方式|
|索引体积|不超过源码体积的 3 倍|磁盘占用|
|关系质量|在独立标注的受支持直接调用集上，L3 definite 准确率目标 ≥99%、召回率目标 ≥95%；同时报告 L1/L2、动态关系和未解析项，不能排除失败样本后只报告高分|独立真值、分语言/关系/来源统计及置信区间；SCIP 仅作引用与导入对照|
|候选质量|报告候选召回、候选错误率、集合大小 P50/P95 与 Agent 阅读成本，不以穷举全部符号获得高召回|动态分发、反射与仓库外消费者专项数据集|
|可复现性|相同源码、构建输入、索引器、模型与规则版本得到相同规范化结果；时间戳等非语义元数据不参与比较|固定排序、哈希和结果规范化；未固定输入必须披露|
|平台支持|引擎、CLI、MCP：Linux、macOS、Windows，x86_64 和 arm64；桌面审查台先验收 macOS 和 Linux，Windows 交付时间依据选定 gpui-kit 版本在本项目上的构建、输入交互与发布验证确定|CI 矩阵，平台和架构分别验收|
|分发方式|Semweft 核心为 Rust 二进制；语法功能不要求用户安装外部语义索引器。L3 另需语言工具链、索引器和仓库依赖；后续若引入本地 Embedding，模型权重单独分发，不进入 v0.1|先验证预编译 Release 与 cargo install，其他包装按需求交付|
|隐私与安全|代码默认不上传；运行分析可在依赖、索引器及可选模型预置后离线进行；依赖获取和首次模型下载单独说明，遥测默认关闭|预置环境网络审计；外部进程的权限与联网由配置约束|

**桌面平台依据（2026-10-30 核查）**：[Zed 于 2025-10-15 发布 Windows 稳定版](https://zed.dev/blog/zed-for-windows-is-here)。[gpui-kit 最新稳定版为 0.8.1](https://crates.io/crates/gpui-kit)，其[官方安装指南](https://gpui-kit.com/docs/installation/)已列出 Windows 10 及以上、MSVC 工具链和 Windows SDK 要求。Semweft 尚未锁定桌面依赖或完成平台验收，交付门槛是本项目验证；具体平台与架构支持以选定版本的矩阵为准。

**安全要求**：

- **接口只读**：MCP 和 HTTP 查询接口只读，不修改代码、授予信任或创建审查记录。初始化、信任和审查提交由 CLI 或桌面端经本地控制接口完成，操作边界见[接口规格](interfaces.md)第 1.6 节

- **索引会执行仓库代码**：rust-analyzer 与 cargo 会运行 build.rs 和过程宏，其他语言的索引器也可能触发构建脚本或包管理器钩子。首次对某个仓库运行 L3 前须由用户确认信任；未确认时只提供已实现的 L1/L2（v0.1 未提供 L2 时仅 L1），将 L3 阻断列为 known_gaps，不作为持续刷新的 pending。capabilities 标注 requires_build 与 requires_trust，index_status 返回当前是否已授权。外部索引器可选在沙箱中运行（限制写入范围、禁用网络）

- **首次信任入口**：用户可在交互式 semweft init 中选择确认，或预先运行 semweft trust；确认提示列出可能执行的构建脚本、过程宏与外部工具。非交互环境可由用户在启动 Agent 前显式执行 semweft trust --accept-build-execution，未提供该标志则返回 trust_required，不读取 stdin 等待确认。semweft init 在非交互环境仅生成配置，不自动授权

- **信任保存与撤销**：信任记录存于仓库之外的用户级配置目录，按规范化仓库根路径及仓库身份登记；semweft.toml、索引包和仓库文件不能自授信任。工作区新增仓库、迁移根路径或仓库身份变化需重新确认，普通源码编辑不重复确认。semweft trust --revoke 撤销当前仓库授权，阻止后续 L3 并取消未完成任务

- **MCP 非交互启动**：semweft mcp 不弹出信任提示，也不通过 stdio 请求确认；未授权时继续提供可用语法查询。Agent 从 index_status 获取 trust 状态与用户可执行的 CLI 提示，capabilities 和 index_status 本身不触发构建。CLI 的 trust_required 是本地控制错误，不把缺少信任当成查询无结果

- **本地传输**：v0.1 MCP 仅 stdio，经当前用户私有 socket 或命名管道连接 daemon，地址与访问权限见架构第 1.1 节。本地 Streamable HTTP MCP 后续评估；交付时只监听 127.0.0.1，校验 Origin 头并要求本地令牌鉴权。此要求与团队版远程 API 分开适用

- **团队版**：远程服务必须支持鉴权、仓库级权限和查询审计；索引中可能包含代码片段，共享索引时要遵循仓库原有的访问权限

## 2. 实验设计

- **独立真值**：由标注者确认引用、调用目标和任务应改点，抽样复核。SCIP 用于导入与引用对照，不作为完整调用图真值；无法确认的动态目标独立标记，不能从分母中悄悄删除。

- **分层数据**：直接调用、宏、泛型、动态分发、注册与字符串引用分别统计；未知机制作为负面与边界案例，首版不以未实现机制作为功能成功门槛。语义变化任务须有人标注业务应改点。

- **公平基线**：相同模型版本、Agent 配置、提示、工具预算、初始快照、测试与时间上限，对比 rg+文件读取、Agent 内置的 LSP 与代码索引，以及 Serena 等符号工具。报告接入 Semweft 的额外索引时间，不能只比较弱检索基线。

- **无 Agent 人工任务**：固定仓库、任务与时间上限，参与者只用 Semweft CLI 与报告，对照 IDE 加 rg；分别测上手任务（定位入口、依赖方向、关键调用链）与改动复核（找出应检查的使用点、识别缺口）的正确率和耗时，并记录参与者对 candidate、pending 与缺口的理解是否正确。

- **效果与成本**：同时报告成功率、漏改和误改率、候选数量、人工审查正确性、耗时与置信区间。Token 包含输入输出、MCP schema/结果和失败重试，记录缓存计费与实际计数。独立建立基线后，在正式评估前登记样本量、重复次数、最小改善幅度及检验方案；Token 收益在任务成功率不下降的条件下评估，口径见路线图第 2 节。

- **上下文预算**：固定 tokenizer 与版本，计入输出序列化开销。精确模式与估算模式分开评测：精确模式验证所有响应不超预算；估算模式报告估算值与实际计数的偏差分布及超出率，用于校准安全余量。最小预算与省略清单分页按[功能规格](features.md) E 节“预算计量”验收，不把预算裁剪当作分析完整。

- **基准版本**：以内部跨文件/契约任务集为主；外部参考固定 SWE-bench Multilingual、Multi-SWE-bench 的数据集 revision，语言子集随版本扩展（v0.1 Rust，v0.2 加 Go，v0.3 加 TypeScript，v0.4 加 Python）。使用隔离的测试集评估，不以开发调参任务宣称提升。
