# Semweft 功能规格

当前另有面向个人使用的 macOS GPUI + gpui-rsx 工作台，已接入源码/符号/全文导航、调用与引用、依赖矩阵/候选循环、度量/Git 热点、书签和变更审查。TS/JS 语法前端通过 `web-experimental` 启用；下文按正式版本规划列出的 GUI 和语言排期不代表这些实验入口不可用。见[桌面说明](../crates/semweft-desktop/README.md)。

**人工可读输出（v0.1）**

不使用 AI 的用户是正式目标用户（见[产品需求](product.md)第 2.2 节）。他们的入口不新增事实类型，而是同一响应的渲染层：

- **同源**：text、Markdown、Mermaid、DOT 输出由与 JSON 相同的响应生成，共用 snapshot_id、epochs、统计与 completeness；顶部固定显示版本、完整性状态、pending 与截断，不能因排版省略

- **缺口汇总**：known_gaps 按类别计数，只展开与本次查询目标或 diff 涉及文件相关的条目，其余给出数量与查看完整列表的命令。原型在 7 万行仓库上观测到上万条缺口（多为标准库与依赖调用、宏、闭包），逐条列出不可读，见[刷新原型进展](prototype.md)第 3 节

- **作用域分组**：#[cfg(test)] 与 tests/ 中的实现和调用方单独分组，默认折叠，避免测试替身干扰生产代码的阅读

- **结构地图**：semweft map 的文本输出按 crate、模块树列出入口与公开符号，不套用 Agent 默认的每模块符号上限，仍按 limit 分页

- **依赖图导出**：crate 级与模块级依赖导出为 Mermaid 或 DOT，边标注来源与确定性（definite 实线、candidate 虚线），仓库外依赖折叠为单个节点，截断的节点与边写入图注；图可直接贴入文档、PR 或交给现成工具渲染

- **影响报告**：impact 的 Markdown 段落固定为摘要、变更符号、候选影响（按调用方模块分组）、已知缺口、未检查项与截断、版本信息；排序稳定，页脚给出对规范化响应计算的报告哈希；面向 PR 评论可按字符上限稳定裁剪并指向完整 JSON

`semweft impls <trait-or-trait-method> --path <prefix>` 对应 `find_implementations`，支持来源、确定性、新鲜度、固定快照和游标参数；非 trait / trait_method 目标返回参数错误。trait 模式列 impl（包括标记 trait 和空 impl），方法模式只为显式覆盖生成 `kind=implements` 关系，未覆盖的默认方法通过 `inherited_defaults` 单独计数。`scope=production/test` 供 text / Markdown 分组：impl 与默认方法继承以 `block.test_only` 为准，显式方法使用 `test_scope()`，不能因单个测试方法把生产 impl 归为 test；它不表示测试已执行或足以验证实现。

语法头部 `syntax_impl_header+name_match` 只支持 L1 candidate，不解析 use 导入、别名和遮蔽。已发布的语义头部绑定 `impl_header_binding:*` 和方法分派 `impl_dispatch:*` 才能增加 L3；LSP 仍为 candidate，已验证并对齐的 SCIP 绑定可提供 definite，不凭 trait 或方法同名假定语义关系。L3 头部绑定可独立识别 use 别名；语法名称不匹配的别名实现不附 L1 name_match，也不出现在 `--source L1` 结果中。仅有可靠 definite 竞争头部绑定且无目标绑定时才进入 `excluded_candidates`；candidate 竞争或确定绑定冲突保留候选并披露 gap。缺少语义证据时，同名 trait 可能误入候选，别名实现可能漏掉。

只有 `relations` 分页。`implementation_counts.total` 为过滤后完整显式实现关系条数，`production`、`test`、`with_semantic_evidence`、`blanket` 都按该集合统计，不随页变化；默认方法继承与排除候选单独计数，不并入 total。`inherited_defaults` / `excluded_candidates` 是完整过滤后的快照元数据，随每页完整返回，不消费分页限额，也不能跨页累加。

当前仅覆盖 Rust 源码中的显式 impl，不展开 derive、过程宏和声明宏生成实现；blanket impl 只列声明，不枚举它覆盖的具体类型；未索引依赖、下游 crate 与其他工作区的实现不可见。negative impl 不作为正向实现。上述边界及语义证据不足、同名歧义、必需方法缺失均通过 `completeness.known_gaps` 披露，不能把空结果或 definite 关系解释为已覆盖全部实现。完整字段与 gap kind 见[接口契约](interfaces.md#find_implementationsrust-trait-实现查询v02-增量)。

### D. 变更影响分析

核心问题是“改这里可能影响哪里，依据是什么，哪些地方还不能判断”。结构影响、规则核验和行为正确性分别报告。

|功能|说明|优先级|
|---|---|---|
|符号级影响范围|输入符号，输出经引用或调用关系推导的候选影响与证据路径；服务维度随本文模块 H 增加|P0|
|Diff 级影响分析|输入 base/head 或 PR，识别两侧变更符号及变更类型，按下方变更模型分别在 base、head 上计算影响范围|P0|
|签名变更检测|v0.2 起按语言和构建配置检查明确的 API 变化；兼容性规则逐项定义|P1|
|受影响测试候选|结合调用图或逐测试覆盖率建议测试，附映射范围与缺口；与项目完整测试策略结合使用|P1|
|限定规则核验|v0.2 起检查明确的签名或依赖规则，列出 findings、未检查项及证据不足|P1|
|风险评分|综合影响范围、调用方数量、热点程度、测试覆盖、所有者数量给出风险等级|P1|
|评审建议|根据所有权信息推荐需要参与评审的人或团队|P1|
|影响报告|首版提供 JSON/Markdown 证据报告，Markdown 段落结构见第 1 节“人工可读输出”；v0.2 增加适合规则发现的 SARIF 与 CI 集成；v0.3 增加自包含的静态 HTML 报告|P0|

**Diff 变更模型（v0.1）**：

- **两侧快照**：head 可为工作区、指定提交或已固定快照。CLI 的 --diff WORKTREE 表示 HEAD 到工作区，--diff REV 表示指定提交到工作区，--diff A..B 表示提交 A 到 B，--diff A...B 表示 merge-base(A, B) 到提交 B；提交比较不隐含工作区改动。MCP 显式传入 base/head 选择器；PR 集成先解析两侧提交。语法和错误规则见[接口规格](interfaces.md)第 1.4 节

- **版本固定**：请求开始时捕获两侧输入，工作区 head 包含未提交与未跟踪的纳入文件；查询确定各自版本对后固定 snapshot_id 与 epochs，后续编辑不替换本次 head。两侧按[核心概念与证据模型](evidence-model.md)第 3 节保留，响应分别返回版本信息

- **符号识别**：把 diff 区间映射到两侧符号，得到 base_symbol、head_symbol 与变更类型 added、deleted、modified、signature_changed、moved、renamed。只改注释或格式的区间单独标注，不计入影响

- **身份匹配**：内容未变文件中的既有声明直接保留；其余先保留限定名与 kind 在两侧均唯一的 exact 匹配，再推断剩余声明的移动、重命名。当前 Rust MVP 比较忽略注释、空白且仅遮蔽声明名称的语法 token 指纹；指纹须在未匹配的两侧各唯一，记为 inferred 并附匹配依据。不复用已配对符号，不依据遍历顺序选择歧义候选；无法唯一匹配时按删除和新增处理。函数体或其他标识符同时变化可能使重命名无法匹配，inferred 不表示已经证明语义身份

- **查询侧**：deleted 在 base 上查调用方与引用，并在 head 上检查残留引用；added 在 head 上查新增引用，trait 或 interface 新实现还会改变动态分发的候选集合；modified、signature_changed 在 head 上查调用方，同时对比两侧关系的增减；moved、renamed 合并 base 的调用方与 head 的引用，列出尚未迁移的使用点

  当前 Rust MVP 对 deleted、renamed、moved 收集 head 中旧名称的出现位置，去重后返回 residual_references，统一标为 L1 candidate。名称匹配未解析绑定，也不能判定迁移状态；同名的无关符号引用和移动后仍然有效的引用均可能出现在候选中。

- **降级**：base 缺少 L3 索引时，先尝试 CI 共享索引或为 base 建立索引；仍不可用时只给已实现的 L1/L2 结果（v0.1 仅 L1），并列入 known_gaps，不拿 head 图代替 base

- **响应**：changes 中每项列出变更类型、两侧符号、匹配方式和查询所用的快照，影响关系标明来自哪一侧

|多 Agent 共享|同一用户、同一 Cargo 工作区的 MCP 与 CLI 客户端连接同一 daemon，共享索引、监听与刷新；多仓库和远程共享后置|P0|

**预算计量**：

- **精确模式**：调用方指定且 Semweft 支持对应的 tokenizer 与版本；按最终序列化后的完整响应计数，包括元数据、证据和省略清单，保证不超预算

- **估算模式**：生效 tokenizer 为 estimated 或不受支持时，按能力清单公布的保守上界估算并预留安全余量；token_count 标明 mode=estimated、估算方法与实际使用模式的原因。请求参数覆盖工作区默认值，估算值与实际计数的保证见证据模型第 2.3 节及质量评测第 2 节

- **最小预算**：响应元数据、completeness 和省略清单首页构成固定开销，能力清单按 tokenizer 公布 min_budget；低于该值返回 budget_too_small，不返回被截断的元数据

- **省略清单**：省略项本身也计入预算，每项只含位置、粒度和续查入口；放不下时只返回 omitted_count 与 omitted_cursor，省略清单按游标分页续取
