# 存储与查询基础层开发进度

按用户确认的顺序推进；每项先实现、测试，再更新结果。

1. [x] 真实仓库刷新基准：`semweft benchmark-storage --revisions N`；临时索引、内存注释编辑、新子进程恢复和峰值 RSS。消费端测试及 Clippy 通过。首轮本仓库 51 个输入文件，1/10 个视图恢复约 152/1122 ms、峰值 RSS 37/166 MB；完整结果位于 `target/storage-baseline.json`。测量包含 L1，未执行构建或 L3，恢复使用温热文件系统缓存。
2. [x] 历史快照按需加载：daemon 使用 `open_lazy`，只保留最新视图及语义基线；保留目录高水位，历史查询延迟校验/加载。14 项存储测试及 CLI 集成通过。基准运行器现独立为 `semweft-bench` crate，CLI 负责采集和子进程适配。
3. [x] 查询缓存数量与内存双预算：默认 8 个/64 MiB，支持配置与动态收紧；3 项缓存测试通过。字节数是载荷与索引的估算权重，活跃查询及刷新根不受缓存预算限制。
4. [x] 可配置保留策略、持久化固定版本与安全对象回收：`snapshots pin/unpin/gc`、`index.retain_snapshots`；16 项存储测试及 CLI 单测通过。
5. [x] 目录增量日志与检查点：独立原子日志段、序号与校验和，64 次事务生成检查点；17 项存储测试通过。
6. [x] 单写者持久化移出查询共享锁：独立写者锁维持事务顺序，查询可在磁盘提交时继续读取；失败批次保留并可重试，并发验证通过。
7. [x] 文件级语法事实对象复用：快照引用各文件内容寻址的事实，保留前端原始顺序及全部字段；兼容旧内联语法对象，回收遍历新引用。19 项存储测试和 CLI 集成通过。
8. [x] 进程退出、写入失败、迁移中断恢复测试：子进程覆盖刷新日志、检查点、旧格式迁移和回收，在 rename 前后及目录同步后退出/注入错误，共 24 种情况。
9. [x] 存储运行指标接入状态查询：恢复/加载/读写/提交/回收指标、固定版本、epoch 高水位和缓存预算/命中/淘汰；真实 daemon 管理命令与重启测试通过。
10. [x] 公共查询协议与存储接口拆分：`semweft-protocol` 提供工具 schema、校验、错误与 IPC 请求；`semweft-storage` 提供持久化模型和 `PublicationStore` 接口；`semweft-store` 实现后端，bench 使用接口读取元数据。

本轮所有性能测量明确区分语法刷新、持久化、查询及恢复；不执行工作区构建或语义工具。
