# 底层基础实现

当前先补齐可复用的基础层，再推进索引、存储和分析能力。以下均已接入现有使用方；整体分层约定见[架构设计](architecture.md)第 4–5 节。

## 已实现

|crate|能力|实际使用方|
|---|---|---|
|semweft-shared|BLAKE3 内容哈希、带命名空间的稳定身份、Position / Span、UTF-8 字节位置校验、UTF-16 坐标换算|core 的输入与证据模型；桌面端捕获源码的哈希和导航坐标校验|
|semweft-algo|泛型 GraphView、有序邻接表、受节点/深度限制的广度遍历、最短前缀路径、超时/取消检查点、截断原因与未展开边界|CLI / daemon 的调用图、符号与 diff 候选影响分析|
|semweft-protocol|工具 schema、参数校验、错误结构与 IPC 请求协议|CLI、daemon 和 MCP|
|semweft-storage|持久化模型、统计及 PublicationStore 后端接口|store 实现、bench 元数据消费|
|semweft-store|不可变视图的查询索引；内容寻址存储、按需恢复、日志检查点、版本固定及安全回收|daemon 发布与恢复；导航、关系、影响和上下文查询|
|semweft-bench|隔离的真实输入刷新、持久化、冷/热查询及恢复测量|CLI 采集输入并适配语言前端与恢复子进程|
|semweft-query|查询执行、快照绑定、证据合并、刷新、采集与语言适配|CLI / daemon / MCP；可直接嵌入的 Engine、QueryService|

shared 与 algo 不依赖其他 Semweft crate，也不相互依赖。storage 只依赖 core；store 依赖 core 和 storage，不链接具体语言。protocol 不依赖 daemon、语言前端或具体存储。bench 不依赖 CLI 或语言库，由使用方注入解析、关系和子进程适配。algo 不执行 IO、不读取时钟、不包含符号或证据模型；查询层负责方向、关系筛选、快照、来源和完整性说明。

### 坐标与持久化兼容

- 公共坐标使用从 1 开始的行号和 UTF-8 字节列号；Span 为左闭右开区间。
- LineIndex 绑定源字符串，为发布校验与 SCIP 转换复用每个文件的行起点表。
- UTF-16 接口使用从 0 开始的行号和 code unit 偏移；拒绝代理对中间位置及溢出坐标。
- CRLF 中的 CR 计入字节位置；行尾插入点和尾部换行后的空行坐标有效。
- 内容哈希与 identity 的 JSON 分段格式保持兼容；core 继续重导出现有 API，语言适配器不必改变导入路径。

### 图遍历契约

- GraphView 按稳定边键、节点键提供邻居；Adjacency 使用 BTreeMap / BTreeSet 保证顺序，输入插入顺序不影响结果。
- 根节点深度为 0，计入节点预算；节点预算为 0 时返回空节点集并把根保留为 frontier。
- 每个节点只展开一次；自环、环和并行边均保留，已访问节点不重复占用节点预算。边的 path 从根向外记录，查询层转换调用方路径方向。
- 节点和边的展开前均执行调用方检查点，查询层据此执行超时或取消。停止时保留已得到的事实、当前节点和仍在队列中的节点。
- 同时触及多个限制时，原因优先级为 cancelled > timeout > node_limit > depth_limit。frontier 描述尚未展开的边界，不是可直接恢复执行的游标。
- 深度限制保留 within_limits 的限定结果；节点限制、超时和取消在查询层标为 partial。
- 过滤图遍历在检查中断后判断边是否纳入；被排除的边不消耗节点/深度预算，即使大量边被过滤也会继续执行取消检查。

### 查询索引与缓存

- IndexedView 一起持有分析视图与对应关系，调用方无法把索引偏移用于另一组事实。按 ID 查符号、按文件查符号/occurrence、按文件和 Span 查当前关系，均不需要扫描整个工作区。
- 关系按 relation_id 排序；入边与出边保存偏移。both 方向合并有序列表并去重自环，不分配临时邻接表，保留并行关系和外部端点。
- 带 origin 的关系保留在图索引中，但不进入当前源码的位置索引，避免用旧快照坐标定位当前源码。
- daemon 在每个工作区内按 snapshot_id + semantic_epoch 缓存 StoredView。引用、诊断、命名空间和 OnceLock 索引在并发读者之间共享；每个缓存视图只在首次使用时合并 L1/L3 事实及建立索引。更新补充证据时移除对应派生缓存。
- 缓存默认同时受 8 个视图、64 MiB 估算权重限制，通过 `index.query_cache_views` / `query_cache_bytes` 配置，0 可关闭缓存。权重计入查询独占的引用、诊断、命名空间及延迟构建的索引；刷新协调器已常驻的分析事实不重复计入。查询缓存独立持有的历史语法快照和语义事实仍按载荷 ×2 计重，跨语义版本共享的快照只计一次。在后续缓存操作及状态读取时重新检查；`storage.query_cache.accounting` 和 `shared_resident_views` 公示此口径。64 MiB 不约束刷新根、活跃读者、语法缓存等进程其他内存，估算也不等于精确堆内存或 RSS。
- 输入清单及采集诊断未变化时，前台扫描复用不可变语法视图，仍保留前后两次内容采集、配置复核、取消检查及发布失败重试。按文件排序的 occurrence 偏移提供位置二分查找，减少逐 Span 树节点分配。
- 引用查询直接选目标入边，调用图按访问节点读取邻接边，证据过滤生成查询自己的结果，不修改共享事实。上下文使用目标的关联边，结构地图使用按文件分组的符号；模糊搜索和名称选择仍保留现有扫描语义。
- 这些是可重建的内存查询索引。首次查询需要建索引；关系按文件缓存，输入内容及被引用名称的目标声明集合变化会失效，缓存估计上限 64 MiB。持久化由下面的 SnapshotStore 独立负责。

分页使用 `index.cursor_cache_count`（默认 256）与 `index.cursor_cache_bytes`（默认 64 MiB）双预算。不可变查询载荷在前后游标间共享，只计一次估计权重，再加每游标 256 字节。普通列表与嵌套历史关系按序列化体积 ×3 计重，续页仅复制当前切片。符号级 `impact_of` / `call_graph` 及测试推荐的影响关系保存每块 256 条、块内字符串字典和 LZ4 编码的原始关系、深度与证据路径，以及展示所需的名称、测试范围和文件哈希；只解码当前页涉及的块，不持有整个分析视图。关系数不超过请求页容量时直接生成 JSON。Diff 报告与测试推荐在需要续页时将其他分页列表按 128 条 LZ4 压缩；diff 的报告聚合仍先计算完整 JSON，符号级测试推荐只为候选证据路径生成 JSON。压缩载荷按缓冲区容量及上下文的估算分配量 ×2 计重，元数据和未压缩列表按序列化体积 ×3 计重。遍历及报告计算仍在分页前完成，统计与截断口径不变。游标可重放，600 秒过期；容量淘汰或单个结果超过预算返回 `cursor_expired`。状态输出包含用量与淘汰数。估计权重不等于 RSS。

### 快照持久化与恢复

新对象按需使用版本化 LZ4 编码，节省不足 32 字节时保留原文；内容哈希始终基于解码后的载荷。兼容原文、LZ4、Deflate，校验解码长度（压缩对象上限 512 MiB）和内容哈希。`snapshots compact` 逐对象原子迁移旧载荷，身份与目录不变，中断后可重试。

- 磁盘格式为 `0.2`，CLI / MCP 响应版本仍为 `0.1`。`views.json` 是目录检查点，记录工作区身份、latest、视图对象引用、固定版本、日志序号和独立于保留历史的 epoch 高水位。
- 对象按 BLAKE3 寻址：`objects/sources` 保存 UTF-8 源码；`objects/syntax` 保存单文件语法事实；`objects/snapshots` 保存 manifest、文件事实引用与紧凑顺序信息；`objects/views` 保存快照引用、epochs、语义事实及补充证据。事实顺序及所有语法字段保持一致，未变化的文件事实跨快照复用。
- 对象写入、同步并原子发布后，最后发布 `journal/<20位序号>.json` 增量目录日志。日志包含序号、工作区身份和校验和；临时文件不参与恢复，已发布日志损坏或断号返回 `index_store_error`。每 64 次事务原子发布完整检查点，然后清理旧日志；GC 强制生成检查点。普通提交写入量随变化目录项增长，检查点大小与内存目录元数据仍随保留视图数增长。
- daemon 用独立写者锁串行处理发布、版本固定和回收。对象序列化、磁盘提交及回收期间释放查询状态锁。回收与历史磁盘加载通过存储读写门协调；新读者在回收后得到 `snapshot_expired`，已取得视图的读者可继续使用。
- 无变化刷新不写对象或日志；失败批次保留供重试。rename 后同步报错时，下一次存储操作重新读取可见事务并重试目录同步，防止旧内存目录覆盖已发布的日志或固定状态。
- daemon 采用 `open_lazy`，启动只读取 latest 和最后一个可用的工作区语义基线，历史载荷在固定版本查询时加载与校验。`open` 保留完整恢复接口。分配 epoch 使用持久化高水位，选择较早 latest、查询 revision 或回收最高历史均不会使编号回退。
- 打开旧 `0.1` 整体 JSON 时先完整校验，再写对象并替换目录；中断可重试。兼容早期 `0.2` 目录元数据和内联语法快照。较旧程序不支持新增目录字段或日志，升级后的索引不支持降级读取。

### 保留与固定版本

`snapshots usage` 按对象类型、检查点、日志和其他文件统计实际物理字节。`index.max_disk_bytes = N` 在刷新后施加磁盘预算，依次减少可选历史；必要根和已缓存/活跃读取视图继续保留。如果这些对象已超过预算，返回 `budget_unmet`。预算是回收目标，提交过程中及必要根超限时允许暂时超出。

```bash
semweft snapshots usage
semweft snapshots gc --keep-last 10 --dry-run --max-bytes 268435456
semweft snapshots gc --keep-last 10 --max-bytes 268435456
semweft snapshots compact
```

预览使用与执行相同的根选择和标记校验，不写文件或改变日志序号；执行提交检查点后才删除对象。`remaining_bytes` 包含检查点和日志，候选回收量 `reclaimed_bytes` 指对象字节。两次操作之间新增发布、固定或活动读者会改变结果。

默认保留全部历史。`index.retain_snapshots = N` 在刷新后尝试保留最近 N 个语法快照及必要根，也可显式执行：

```bash
semweft snapshots pin SNAPSHOT --epoch EPOCH
semweft snapshots unpin SNAPSHOT --epoch EPOCH
semweft snapshots gc --keep-last 10
```

省略 epoch 时选择该快照已发布的最高语义版本。固定状态随目录持久化。GC 始终保留 latest、可用语义基线、固定版本和活跃读者，最近 N 个快照保留其全部语义版本；实际保留量可能大于 N。GC 先校验可达对象并提交精简目录，再删除无引用的正规哈希对象，删除中断只留下垃圾。重复执行可完成清理。分页结果已存于内存，daemon 重启后游标失效；需要长期固定版本的调用方应显式 pin。

`status.storage` 提供本进程恢复/加载/读取/提交/回收计数和耗时，以及目录序号、高水位、固定版本和缓存命中/淘汰/估算权重。写入字节累计来自成功提交的对象与目录统计，不包含失败写入的临时文件、物理块放大和 fsync 成本；指标在进程重启后重新累计。

### 真实输入基准

```bash
cargo run --locked --release -p semweft-cli -- --workspace . benchmark-storage --revisions 10 --runs 3 --save-input target/performance-input.json > target/performance-before.json
cargo run --locked --release -p semweft-cli -- benchmark-storage --input target/performance-input.json --runs 3 --baseline target/performance-before.json
cargo test --locked -p semweft-store write_volume_grows -- --nocapture
```

`semweft-bench` 使用捕获的真实工作区输入，对内存副本追加注释，在临时索引内持久化；每轮试验和恢复均运行于新子进程。冻结输入固定内容、版本与编辑序列，报告 min/P50/P95/max、采集、解析发布、持久化、实际写入字节、冷查询、1000 次热查询及支持平台的进程峰值 RSS；拒绝输入身份或查询校验不一致的对照，并比较相同对象的原文/LZ4/Deflate 编码。它不修改仓库、不执行构建或 L3。冷查询包含建立派生索引；恢复文件系统缓存为温热状态。分位数受样本量限制，3 轮只能提供初步信号，不等同于质量评测。

本轮原始记录在 `target/storage-baseline.json`（较早 eager 基线）和 `target/storage-after.json`（优化后）。两次开发过程中输入文件数发生变化，不能视为相同输入的严格前后延迟对比；20 次合成刷新累计写入 79,986 字节，对照整体 JSON 重写为 18,346,968 字节。优化后第 1/10 次样本的恢复与写入结果见[本轮进度](#存储与查询基础层开发记录)。

### 可复现的查询测量

```bash
cargo run --locked --release -p semweft-store --example query_index -- 20000 1000
```

2026-10-31，在本机 Apple M3 Pro / macOS arm64 的 release 构建上，使用 20,000 个合成符号、20,000 条已合并关系，对 1,000 个目标各做一次入边与符号查询：

|阶段|本次测量|
|---|---|
|建立全部内存索引|9.269 ms|
|每次全量扫描，共 1,000 次|65.910 ms|
|复用索引，共 1,000 次|0.555 ms|

两种查询结果的校验和均为 2,000。该测量固定为单次合成负载，展示查找成本与一次性构建成本，不包含源码采集、解析、L1/L3 合并、IPC、JSON 序列化或完整查询，不能推导真实仓库的延迟分位数和内存门槛。

## 验证范围

基础层测试覆盖 Unicode、emoji、CRLF、空文件、末尾空行、非法边界与极端坐标，以及持久化哈希兼容。图算法除固定案例外，枚举全部 512 个三节点有向图，与独立传递闭包比对可达节点和边；另验证输入顺序、最短路径、自环、环、并行边、预算和中途取消/超时。

现有 workspace 和桌面端回归继续检查调用方向、diff、固定快照、分页、共享 daemon 与导航。这里的测试不代替[质量目标](quality.md)中的真实仓库性能和独立语义质量评测。

索引测试与全量扫描逐一比对三个方向的关系，覆盖自环、并行边、外部端点、原始符号顺序和历史坐标；缓存测试覆盖版本对隔离、并发初始化和 LRU 淘汰。查询回归验证不同来源过滤不污染共享事实，以及预热后编辑、固定旧版本和 daemon 重启的结果一致性。

持久化测试覆盖源码和文件语法事实复用、完整字段与顺序恢复、语法与语义共享快照、补充证据、按需加载、高水位、缓存预算、固定版本、活跃读者、回收、日志重放和检查点、各级对象损坏及非法引用。子进程在刷新、检查点、迁移、回收的 rename 前后及目录同步后退出或注入写入错误，共 24 种组合；另覆盖同步报错后的进程内重试。CLI 回归检查刷新前后历史对象未被替换、重启后继续复用、固定旧快照查询及真实 daemon 的旧格式迁移。

### 刷新与库边界

Rust 监听刷新按文件元数据与事件复用源码，每 5 秒强制重读对账，前台最新查询仍完整核对；Go/Web 和外部依赖继续全量采集。Rust/Go/Web 缓存每个文件的完整语法事实，未变化文件跳过 AST 提取和骨架构建；采集和解析在查询状态锁外执行，发布前再次核对输入与分析配置。

`semweft-query` 不依赖 CLI、IPC 或 MCP，提供 `Engine` 和 `QueryService`。宿主负责进程级写锁、监听和退出时 `Engine::shutdown`；配置、信任、固定快照、取消及错误语义保持一致。直接嵌入方式见[库说明](../crates/semweft-query/README.md)，本轮实现及测试记录见下文[第二轮基础层开发记录](#第二轮基础层开发记录)。

### 同输入实测

2026-10-31，本机 release 构建，59 个文件、约 801 KB 源码，10 次注释编辑；优化前后均用同一冻结输入、各 3 个新进程运行。输入为 `target/performance-input.json`，前后报告为 `target/performance-before.json` / `target/performance-after.json`，所有运行的查询校验与基线一致。以下为第 10 次刷新样本的 P50，MB 使用十进制：

|指标|优化前|优化后|

|解析与发布|441.4 ms|13.0 ms|
|持久化|169.6 ms|75.8 ms|
|该视图首次关系索引与查询|105.2 ms|69.9 ms|

|发布进程峰值 RSS|168.2 MiB|231.8 MiB|

缓存用内存换取重复刷新成本：本次峰值 RSS 增加约 38%，不能把字节预算等同于进程内存上限。首次进程冷查询 P50 为 123.3 → 124.1 ms，近似持平；第 10 个视图的首次查询可以复用前面视图的文件关系缓存，不能称为完全冷进程查询。关系缓存权重按结构体和字符串分配容量估计，避免为计量再次序列化全部边。三个样本的分位数仅供初步对照，不代表稳定性能门槛；本基准不覆盖构建、L3 或真实 rust-analyzer。
